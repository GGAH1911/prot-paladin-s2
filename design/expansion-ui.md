### 1-2. 메커니즘 키로 "내 기술로 대응" 자동 생성

던전 항목에 무엇을 해야 하는지(메커니즘 키)를 달고, 전문화 키트가 "내 기술"로 답합니다.

```js
// 지금
["tb", `${A("Hydrastrike")} 머리 3연타 → SotR`]
// 바꾼 뒤 (공용 층)
["tb", `${A("Hydrastrike")} 머리 3연타`, { m: ["tankbuster"] }]
// 키트 (전문화 층)
answers: { tankbuster: "→ {Shield of the Righteous}" }        // 보호 성기사
answers: { tankbuster: "→ {Death Strike}, 위험하면 {Vampiric Blood}" } // 혈기 죽음의 기사
```

| 키 | 붙는 곳 | 키트가 채우는 값 |
|---|---|---|
| `kick` | 차단해야 하는 시전(필수/권장 표시 유지) | 내 차단기 이름·쿨타임. 없으면 "차단기 없음 → 기절·제어로" |
| `stun`, `aoeStop`, `cc` | 기절·방향 상실로 막을 수 있는 시전·몹 | 내 기절·광역 제어. 보스면 `bossImmune` 기술 제외 |
| `tankbuster` | 큰 물리 한 방 | 탱커: 방어 유지기. 힐러: 탱커에게 외부 생존기. 딜러: 표시 안 함 |
| `aoe` | 파티 전체 피해 | 힐러: 광역 치유기. 딜러·탱커: 개인 생존기 |
| `dispel.poison` 등 | 해제 가능한 디버프 | 내가 풀 수 있으면 기술 이름, 없으면 담당 역할 |
| `prio` | 먼저 잡아야 하는 몹 | 딜러: 단일 폭딜기·대상 지정 팁 |
| `freedom`, `move` | 이동 방해·장판 | 해제기·이동기 |

**해제 담당표**: 지금은 html에 "담당: 나"를 손으로 써 두었습니다. 바꾼 뒤에는 키트의 `dispel: ["poison","disease"]`에 있으면 "나", 없으면 역할 기본값(마법 → 힐러, 저주 → 해당 직업)으로 계산합니다.

### 1-3. 조합 규칙

- 직업 → 전문화 → 영웅 특성은 `roster.json`에서 옵니다. 전문화 하나당 영웅 2개입니다(드루이드 4개 전문화, 악마사냥꾼 3개 전문화도 각 전문화는 2개).
- 던전 → 보스·일반몹 구간은 공용 층 하나입니다. 모든 전문화가 같은 던전 목록과 같은 보스 순서를 봅니다.
- 화면에 그릴 때 보스 카드 하나는 **공용 문장 + 역할 문장 + 전문화 문장 + (지금 영웅의) 영웅 문장**을 태그 순서대로 합쳐서 보여 줍니다. 상세 공략(`deepHtml`)은 지금처럼 "개요 → 단계 → 역할 운영 → 전문화 활용 → 파티 공통" 순서를 유지하고, 제목만 데이터에서 읽습니다("탱커 운영" / "힐러 운영", "보호 성기사 활용" / "혈기 죽음의 기사 활용").

**휴대폰 탭 수**
- 첫 방문: 역할 1 + 전문화 1 + 영웅 1 = **3탭**. "나중에(추천 영웅으로 시작)"도 탭 한 번이라 최소도 3탭입니다. 2탭으로 줄이려면 전문화를 누르는 즉시 추천 영웅으로 넘어가고 영웅은 치트시트 토글로 바꾸게 해야 합니다(결정 질문 11번).
- 재방문: `/`에 들어오면 저장된 전문화로 바로 넘어가니 **0탭**입니다.
- 같은 역할 안 전문화 바꾸기: 빠른 전환 줄 **1탭**.
- 다른 역할로 바꾸기: 전문화 변경 → 역할 → 전문화 = **3탭**.

**40개를 보여 주는 방법**
- 역할을 먼저 고르게 해서 한 번에 보는 수를 줄입니다(탱 6, 힐 7, 딜 27).
- 딜러 27개는 직업 13개로 묶습니다. 묶음마다 직업 이름 머리 + 전문화 칩 1~3개를 두고, 휴대폰 2열로 배치하면 약 두 화면 반 분량입니다.
- 직업색은 칩 왼쪽 점과 선택 테두리에만 씁니다.

## 3. 역할별 렌즈 (태그)

**결론**: 기존 태그 6개는 그대로 두고, 새 태그를 **3개**(광역 피해 `aoe`, 우선 처치 `prio`, 제어 `cc`) 추가합니다. 역할마다 기본 켜짐과 순서만 다르게 합니다.

| 태그 | 뜻 | 탱 | 힐 | 딜 |
|---|---|---|---|---|
| 탱버 `tb` | 탱커 큰 한 방 | 1 켬 | 3 켬(외부 생존기) | 끔 |
| 차단 `int` | 필수/권장 차단 | 2 켬 | 5 켬 | 1 켬 |
| 위치 `pos` | 끌기·산개·장판 위치 | 3 켬 | 6 켬 | 7 켬 |
| 회피 `dodge` | 피할 장판·전방 공격 | 4 켬 | 4 켬 | 4 켬 |
| 해제 `disp` | 해제할 디버프 | 5 켬 | 2 켬 | 6 켬 |
| **제어 `cc`** 신규 | 기절·방향 상실로 막는 시전·몹 | 6 켬 | 끔 | 3 켬 |
| **광역 피해 `aoe`** 신규 | 파티 전체 피해 타이밍 | 7 켬 | 1 켬 | 5 켬(개인 생존기) |
| **우선 처치 `prio`** 신규 | 먼저 잡을 몹 | 8 켬 | 끔 | 2 켬 |
| 참고 `tip` | 기타 | 9 켬 | 7 켬 | 8 켬 |

- **새 태그가 필요한 근거**: 지금 우선 처치 정보는 `pos` 안에 "최우선 처치"라는 글로 섞여 있습니다(예: TRASH `Ritual Chieftain 최우선 처치`). 힐러의 광역 피해 정보는 `DETAIL.phases` 안의 `[참고]` 문장에 흩어져 있습니다. 태그가 없으면 역할별 필터로 걸러 낼 수 없습니다.
- **개인 생존기 태그는 만들지 않습니다.** `aoe`·`tankbuster` 항목에 키트가 "내 생존기"를 붙이는 방식으로 충분하고, 태그가 10개를 넘으면 휴대폰에서 필터 줄이 두 줄이 됩니다.
- **필터 기억**: 역할별로 `wg:tags:<role>`에 저장합니다. 같은 역할 안에서 전문화를 바꾸면 필터가 유지되고, 역할이 바뀌면 그 역할의 저장값(없으면 기본값)을 씁니다.

## 4. 시각 디자인 토큰

### 4-1. 방향 확인 결과

- 애플 제품 페이지 본문색은 `#1D1D1F`이고, 섹션 위아래 여백은 144px, 섹션 제목은 48~56px(굵기 600)입니다.
- 사양 페이지 본문은 17px/27px이고, 행 약 80개를 왼쪽 항목명·오른쪽 값으로 촘촘히 놓습니다.
- **다른 점 1**: 애플 구매 페이지는 데스크톱에서 왼쪽 이미지(859px)·오른쪽 선택 열(328px)의 **2단**입니다. 요청하신 "한 단"과 다릅니다.
  - **대안**: 선택 화면은 데스크톱에서도 한 단(최대 폭 980px)으로 두고, 이미지 자리에 "고른 값 요약"을 위쪽 고정 바로 옮깁니다. 요약이 늘 보이는 효과는 같고, 한 단 흐름도 지킵니다.
- **다른 점 2**: 제품군 페이지의 모델 아이콘 줄은 **고정되지 않고** 스크롤하면 사라집니다. 대신 제품 페이지 상단 고정 바의 제품명이 **같은 제품군 모델 드롭다운**을 겸합니다("현재 보고 있는 모델" 표시).
  - **대안**: 빠른 전환 줄은 S2 맨 위에 한 번만 두고 스크롤과 함께 올라가게 합니다. 고정 바의 전문화 이름을 누르면 같은 역할 전문화 목록이 드롭다운으로 열리게 해서 두 역할을 나눕니다.

## 5. 파일·URL 구조

### 5-1. 한 파일에 넣으면 얼마나 커지나

- 공용 층은 약 330KB(던전 툴팁 200KB 포함)이고, 전문화 층은 키트·툴팁·문장·가이드를 합쳐 전문화당 50~70KB로 추정합니다.
- 40개를 한 파일에 넣으면 약 **2.6~3.1MB**가 됩니다. 휴대폰 첫 로딩이 지금(370KB)의 8배가 되고, 내가 쓰지 않는 39개 전문화 데이터를 매번 받게 됩니다.
- **나누면**: 첫 방문 = 공용 330KB + 역할 약 15KB + 전문화 약 60KB ≈ **400KB**로 지금과 비슷합니다. 공용 층은 모든 전문화가 같이 쓰므로 한 번 받으면 캐시됩니다.

### 5-2. 주소 방식 비교

| 방식 | 예 | 장점 | 단점 |
|---|---|---|---|
| **A. 폴더마다 페이지 파일(추천)** | `/paladin/protection/#altar` | 공유 링크가 사람이 읽을 수 있음. 새로고침·즐겨찾기 안전. 404가 거의 없음. Murlok과 같은 구조 | 페이지 셸 약 160개 생성 필요(스크립트로 해결) |
| B. 해시 주소 | `/#paladin/protection/altar` | 파일 하나 | 주소가 길고 읽기 어려움. 던전 hash와 섞임. 기존 `/#altar` 즐겨찾기와 충돌 |
| C. 404.html로 모든 경로 처리 | `/paladin/protection/`를 404가 받아 렌더 | 파일 하나 | 모든 방문이 HTTP 404 응답으로 시작함(링크 미리보기·검색 노출 불리, 일부 앱 내 브라우저가 오류 화면 표시) |

**추천 A안 세부**
- `tools/build.mjs`가 `roster.json`을 읽어 폴더와 셸 파일을 만듭니다. 셸은 전문화 ID만 적고 공용 엔진을 불러오는 수십 줄짜리 파일입니다.
  ```
  /index.html                         S1 선택 (저장값 있으면 S2로 replace)
  /specs/index.html                   S5 단독 페이지 (JS 없이도 40개 링크)
  /<class>/<spec>/index.html          S2 치트시트 (status=soon이면 S7로 그림)
  /<class>/<spec>/<hero>/index.html   S3 스킬 가이드 (정적 HTML로 생성, 툴팁만 JS)
  /<class>/<spec>/compare/index.html  S4 비교
  /404.html                           S9
  /guides/templar.html                S8 스텁 → /paladin/protection/templar/
  /guides/lightsmith.html             S8 스텁 → /paladin/protection/lightsmith/
  /files/*.pdf                        그대로 유지
  /assets/app.js, app.css             엔진
  /data/core/*.json, /data/role/*.json, /data/spec/*.json, /data/roster.json
  ```
- 개수: 치트시트 40 + 가이드 80 + 비교 40 = **160개 셸**. 모두 스크립트가 만들고 사람이 손대지 않습니다.
- 던전은 지금처럼 `#altar`로 둡니다. 영웅은 저장값을 쓰고, 공유 링크에만 `?hero=`를 붙입니다.

### 5-4. 기존 주소·저장값 이어받기

| 기존 | 처리 |
|---|---|
| `/` 즐겨찾기 | 새 S1이 `pp-*` 또는 `wg:spec`을 보고 `/paladin/protection/`으로 replace |
| `/#altar` | 같은 규칙 + hash 유지 → `/paladin/protection/#altar` |
| `/guides/templar.html` 등 | 파일을 남겨 두고 내용을 리다이렉트 스텁(`<meta http-equiv="refresh">` + `location.replace`)으로 교체 |
| `/files/*.pdf` | 그대로 둡니다. 인쇄용 CSS(6번)가 자리 잡으면 링크만 가이드 페이지로 바꿉니다 |
| `pp-hero` | `wg:hero:paladin/protection`으로 복사 |
| `pp-tiplang` | `wg:lang`으로 복사(기본 English 유지) |
| `pp-tab` | `wg:tab`으로 복사 |
| `pp-open` | `wg:open`으로 복사(키 `deep-altar-Rav'i` 형식 그대로) |
| 위 중 하나라도 있음 | `wg:spec = "paladin/protection"` 저장 → 기존 사용자는 선택 화면을 보지 않음 |

`pp-*`는 지우지 않습니다. 문제가 생겨 되돌릴 때 옛 페이지가 그대로 읽을 수 있게 하기 위해서입니다.

### 6-2. PDF 대신 인쇄용 CSS

- A4 PDF 80개는 패치마다 다시 만들어야 해서 비현실적입니다.
- 가이드 페이지에 `@media print`를 넣어 브라우저 인쇄(또는 "PDF로 저장")로 A4 한 장이 나오게 합니다. 지금 PDF를 만들 때 쓴 규칙(여백 축소, 글자 12~13px, 툴팁·버튼 숨김, 아이콘 32px)을 CSS로 옮기면 됩니다.
- 보호 성기사의 기존 PDF 두 개는 0단계 동안 유지합니다. 인쇄 결과가 같아지면 링크를 인쇄 안내로 바꿉니다.

**검수·갱신 부담 줄이기**
1. **로스터 자동 생성**: 이번에 쓴 방법(wago.tools 게임 테이블 → 전문화·영웅 연결 계산)을 `tools/roster.mjs`로 남깁니다. 패치 때 빌드 번호만 바꿔 다시 돌리면 한글 공식명까지 갱신됩니다.
2. **한글 이름 자동 대조**: 기술·NPC 한글명은 툴팁 API(`locale=1`)와 기존 `audits/` 방식으로 자동 대조합니다. 사람은 대조에 실패한 이름만 봅니다. 지금 `audits/ko-names-wowhead.md`에서 141개 중 132개가 자동으로 맞았으니, 사람이 볼 몫은 10% 안쪽입니다.
3. **공용 층 우선**: 새 문장을 쓸 때 "모든 전문화에 해당하는가"를 먼저 묻고, 해당하면 공용·역할 층에 씁니다. 전문화 층이 얇을수록 전문화 수에 비례해 늘어나는 검수량이 줄어듭니다.
4. **대응 문구 자동화**: 메커니즘 키 + 키트로 차단·해제·탱버 문구를 자동으로 만들면, 전문화마다 사람이 쓰는 문장이 보스당 3~4줄에서 1~2줄로 줄어듭니다.
5. **오래된 데이터 표시**: 전문화 파일의 `patch` 값이 현재 패치보다 오래되면 치트시트 상단에 "12.1.5 이전 기준" 표시를 자동으로 띄웁니다.

### 8-3. 1단계: 탱커 6개

- **순서 제안**: 혈기 죽음의 기사 → 방어 전사 → 수호 드루이드 → 복수 악마사냥꾼 → 양조 수도사. 탱커 선택률이 높은 순서로 잡았습니다(선택률 수치는 이번에 확인하지 않음, 미확인).
- 전문화 하나마다 `spec-checklist.md` 13개 항목을 채웁니다. 공용·탱커 층은 그대로 씁니다.
- **첫 전문화(혈기)를 만들 때 항목별 시간을 기록합니다.** 이 값이 2단계 이후 범위를 정하는 근거가 됩니다.

**완료 기준**: 6개 전문화가 `ready`이고, 각 전문화에서 28보스 전부에 전문화 문장이 1줄 이상 있으며, 한글 이름 자동 대조 실패가 0건입니다.

**사용자가 확인할 것**: 보호 성기사가 아닌 탱커 하나를 실제로 플레이해 보고, "내 기술로 대응" 줄이 맞는지 봅니다.

### 8-4. 2단계 이후: 힐러 7개, 딜러 27개

힐러·딜러는 전문화 층보다 먼저 **공용 층에 역할 시점 문장을 채워야** 합니다. 지금 문장은 탱커 시점이기 때문입니다.

| 추가로 채울 것 | 대략 분량(추정) |
|---|---|
| 힐러 역할 층: 보스별 광역 피해 타이밍·외부 생존기 대상 | 28보스 × 3~4줄 ≈ 100줄 + 일반몹 구간 60곳 |
| 딜러 역할 층: 우선 처치·차단 담당·개인 생존기 구간 | 28보스 × 3줄 ≈ 85줄 + 일반몹 구간 60곳 |
| 기존 항목에 `aoe`·`prio`·`cc` 태그와 메커니즘 키 붙이기 | 540항목 한 번(0단계와 겹치면 줄어듦) |
| 전문화 층(힐러·딜러는 탱커보다 얇음) | 전문화당 보스별 1~2줄 ≈ 30~50줄 |

- 역할 층은 **한 번만** 쓰면 그 역할 전문화 전부가 씁니다(힐러 7개, 딜러 27개).
- 전문화 수가 가장 많은 딜러 27개는 전문화 층을 얇게 유지하는 것이 핵심입니다. 키트 자동 문구만으로도 쓸 만한 치트시트가 나오도록 역할 층을 먼저 완성합니다.
- 구체적인 범위와 일정은 **1단계 실측값**으로 정합니다. 예를 들어 혈기가 15시간 걸렸고 그중 8시간이 보스 문장이라면, 딜러 전문화는 보스 문장이 절반이므로 약 10시간 × 27개 = 270시간이 됩니다. 이 경우 인기 전문화 10개만 `ready`로 하고 나머지는 `partial`로 두는 식으로 범위를 줄입니다.

### 8-5. "준비 중" 표시

- `status`가 세 가지입니다.
  - `soon`: 공용+역할 층만 있음
  - `partial`: 전문화 층 일부 있음
  - `ready`: 전부 있음
- S5 선택기에서 `soon`·`partial`은 회색 배지("준비 중"/"일부")로 보이지만 **고를 수 있습니다.** 고르면 S7에서 공용+역할 층 치트시트를 그대로 보여 주고, 상단에 "이 전문화의 기술 대응은 준비 중입니다. 던전 공략과 ○○ 운영은 볼 수 있습니다." 배너를 띄웁니다.
- 힐러·딜러처럼 역할 층도 없는 경우에는 공용 층(개요·단계·파티 공통)만 보여 주고, 배너 문구를 "역할 팁도 준비 중"으로 바꿉니다.
- 가이드·비교 버튼은 비활성으로 두고 이유("가이드 준비 중")를 옆에 적습니다.

### 8-6. 비현실적인 부분과 대안

| 비현실적 | 이유 | 대안 |
|---|---|---|
| A4 PDF 80개 | 패치마다 80개 재생성 | 인쇄용 CSS(6-2) |
| 가이드 80개 수작업 HTML | 카드 30여 장 × 80 = 약 2,500장 | JSON + 생성 스크립트, 영웅 공통 카드는 한 번만 |
| 40개 전문화 전체 문장 검수를 사람이 전부 | 전문화 수에 비례해 증가 | 공용·역할 층 우선, 대응 문구 자동화, 한글명 자동 대조 |
| 40개를 한 HTML 파일에 | 약 3MB | 층별 JSON 분리(5-1) |
